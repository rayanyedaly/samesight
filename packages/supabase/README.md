# @samesight/supabase

A PowerSync backend connector for Supabase that does not lose writes.

```bash
npm install @samesight/supabase @powersync/common @supabase/supabase-js
```

```ts
import { SupabaseConnector } from "@samesight/supabase";

await db.connect(new SupabaseConnector({ supabase, powersyncUrl: "https://<instance>.powersync.journeyapps.com" }));
```

- **One call per transaction.** Each local transaction uploads as a single `apply_batch` RPC, so it commits or fails as a unit, and RLS checks every row as the signed-in user.
- **Failures sorted, not guessed.** `classifyUploadError` sorts each failure into retry (timeouts, deadlocks, network), reauth (expired or tenant-less token), stuck (the server is at fault: kept queued, `onStuck` tells you) or reject (constraint, RLS, explicit refusal). Only a reject leaves the queue.
- **Refused writes are kept.** Before a rejected transaction leaves the queue, its content is written to a local-only `RejectedWrite` table (and, best effort, to the server's `record_rejection`), so the app can show the user what was refused instead of dropping it silently.
- **Never under another user's session.** With `ownerId`, uploads and credentials are refused while the Supabase session belongs to someone else, for example after another tab signed in.
- **Append-only helpers.** `latestOnly` reduces a table where corrections supersede earlier rows to the current rows, resolving forks by server sequence; `earlierVersions` lists a row's history.
- `pendingUploadCount` and `hasUnsyncedWrites` read the upload queue, for sign-out prompts.

The `apply_batch` and `record_rejection` functions it calls are generated by [`samesight`](https://www.npmjs.com/package/samesight) from your access policy. Without a samesight policy, provide functions with the same contract, or rename them with `functions: { applyBatch, recordRejection }`.

| Option | |
| --- | --- |
| `supabase` | The Supabase client. |
| `powersyncUrl` | The PowerSync service endpoint. |
| `onRejected` | Persist a refused batch before it leaves the queue. Default: `recordRejectedLocally`, which needs `rejectedWriteTable` in the client schema (the generated schema has it). |
| `onStuck`, `onUploaded` | Held batch notice, and its all-clear. |
| `isSignedIn` | Whether the device still holds a session, so an unrefreshable token offline is retried rather than treated as signed out. |
| `ownerId` | The user whose database this is; anything else is refused. |
| `functions` | Names of the RPCs. |
